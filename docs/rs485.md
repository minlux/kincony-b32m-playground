# RS485

## Documented pins

From the KinCony forum I/O definition thread (tid=9089):

- RXD: GPIO38
- TXD: GPIO39

That's all that's documented — see `include/pins.h` (`PIN_RS485_RX` / `PIN_RS485_TX`).

## Open question: direction (DE/RE) control pin

RS485 is half-duplex, so a transceiver chip needs to know when to drive the bus
(transmit) vs. listen (receive). There are two ways boards typically handle this:

1. **Manual control** — MCU toggles a DE/RE GPIO high before writing and low
   after, e.g. an SP3485-family transceiver.
2. **Auto-direction sensing** — a transceiver like MAX13487E watches the UART TX
   line itself and switches direction automatically, needing no GPIO at all.

KinCony's own **T32M** board (a sibling product) explicitly uses manual control:
an `RS485_EN` GPIO (active-high = transmit) driving an **SP3485EEN** transceiver
(see forum tid=8242, post pid=22228). Its Arduino example does
`digitalWrite(RS485_EN, HIGH)` before sending and `LOW` afterward.

For the **B32M**, no DE/RE pin is mentioned anywhere in KinCony's forum I/O table,
schematics, or wiring-example thread (tid=9261, which only has an image
attachment, not inspected here). Two possibilities:

- The B32M uses an auto-direction transceiver and genuinely needs no control pin
  (a plain `Serial.begin()`/`Serial.write()` would just work), or
- The documentation is incomplete and there is an undocumented DE/RE pin —
  possibly one of the three "free, no pull-up" GPIOs listed in `pins.h`
  (13, 14, 21), since those are the same GPIO numbers T32M happens to use for
  its RS485 RX/TX/EN trio (coincidence, or copy-paste artifact in KinCony's
  docs — unclear).

**Do not assume auto-direction and just start writing to the port.** If it's
actually a manually-controlled SP3485 and no DE/RE pin is ever asserted, transmit
data may not reach the bus at all (or only garbled data, depending on the
transceiver's default state).

## How to resolve before writing RS485 code

- Check the B32M schematic (not found publicly as of this writing) for the
  transceiver chip model and any DE/RE net.
- Or ask on the KinCony forum / support (web@kincony.com) which transceiver the
  B32M uses and whether a direction pin exists.
- Or test empirically: wire a receiver, attempt a transmission with no DE/RE
  handling, and check with a logic analyzer / second RS485 node whether data
  arrives cleanly.
